Embeddings and Vector Search

A text embedding is a numeric vector that represents the meaning of a piece of text. An embedding model converts a sentence or paragraph into a list of numbers (for example, a few hundred to a few thousand floating-point values) such that pieces of text with similar meaning end up with vectors that are close together in that numeric space.

Why embeddings matter for RAG

Retrieval-Augmented Generation depends on finding the document chunks most relevant to a user's question. Rather than matching exact keywords, embeddings let the system compare meaning: the query is embedded with the same model used for the documents, and the resulting vector is compared against every stored document vector. This is called semantic search, and it can find relevant text even when the wording is different from the question.

Cosine similarity

The most common way to measure how close two embedding vectors are is cosine similarity, which measures the angle between two vectors rather than their raw distance. A cosine similarity near 1.0 means the vectors point in almost the same direction (very similar meaning); a value near 0 means they are unrelated. This project's retrieval.py module computes cosine similarity between the query embedding and every stored chunk embedding, then keeps the top-scoring chunks as context for the chat model. A minimum relevance score can also be enforced, so that if nothing in the knowledge base is actually similar enough to the question, the system does not pass irrelevant context to the model at all.
